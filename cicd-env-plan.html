Secure Env + CI/CD Plan

How environment secrets flow from GitHub to production without ever touching the repository.

Strategy
Single secret — base64-encoded .env
With 50+ env vars, managing them one-by-one in GitHub Secrets is painful. Instead, prepare a production .env locally, base64-encode it, and store the result as one GitHub Secret (ENV_PROD). The deploy job writes it to the server on every deploy. Individual secrets are used only for SSH credentials.
GitHub Environment with approval gate
Create a GitHub Environment named production. Attach all production secrets to it and require at least one reviewer before any deploy runs. This means a bad push can't auto-deploy — someone has to approve it.
Pipeline Shape
Push to main
→
PHPUnit Tests
→
👤 Reviewer Approves
→

Feature branch pushes and PRs run tests only — no deploy job, no production secrets exposed.

One-Time Setup Steps
1
Generate a deploy SSH keypair
Run locally — do not use your personal key.
ssh-keygen -t ed25519 -C "tsia-deploy" -f ~/.ssh/tsia_deploy -N ""
2
Authorise the key on the server
SSH in once and append the public key.
cat ~/.ssh/tsia_deploy.pub | ssh vineyardtransportationke@34.173.51.226 \
  "cat >> ~/.ssh/authorized_keys"
3
Add the private key to GitHub Secrets
GitHub → Repo → Settings → Environments → production → Add secret → SSH_PRIVATE_KEY → paste the contents of ~/.ssh/tsia_deploy (the private file, no extension).
4
Base64-encode the production .env
Run on a machine that has the full production env file. Paste the output into the ENV_PROD secret.
base64 -w0 /path/to/prod.env | pbcopy   # macOS
base64 -w0 /path/to/prod.env | xclip    # Linux
5
Create the GitHub Environment
GitHub → Settings → Environments → New → name it production → enable Required reviewers → add yourself (and any other approver). Add all four secrets there, not at the repo level.
6
Add the workflow file to the repo
Create .github/workflows/deploy.yml — see below.
Workflow File

Save as .github/workflows/deploy.yml

name: CI / CD

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:

  # ── Run on every push / PR ───────────────────
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
          extensions: mbstring, pdo_sqlite, bcmath, zip
          coverage: none
      - run: composer install --no-interaction --prefer-dist --no-progress
      - run: cp .env.example .env && php artisan key:generate
      - run: php artisan test --parallel

  # ── Deploy only when main passes + reviewer approves ─
  deploy:
    needs: test
    runs-on: ubuntu-latest
    environment: production   # ← triggers the approval gate
    if: github.ref == 'refs/heads/main'
    steps:
      - name: Deploy via SSH
        uses: appleboy/ssh-action@v1
        with:
          host:     ${{ secrets.SSH_HOST }}
          username: ${{ secrets.SSH_USER }}
          key:      ${{ secrets.SSH_PRIVATE_KEY }}
          script: |
            # Write production .env from secret
            echo "${{ secrets.ENV_PROD }}" | base64 -d \
              > /var/www/html/.env

            # Run the existing deploy script
            cd /var/www/html
            bash deploy.sh
Rules
Commit these
  • .env.example — template with no values
  • .github/workflows/deploy.yml
  • deploy.sh
  • docker-compose.yml
Never commit
  • .env — ever, on any branch
  • .env.production or any env variant
  • SSH private keys
  • API keys, tokens, passwords inline
Updating the Production Env Later
When a value changes (new API key, rotated secret):
  1. Edit your local copy of the production .env
  2. Re-run base64 -w0 prod.env
  3. Update the ENV_PROD secret in GitHub (Settings → Environments → production)
  4. Trigger a deploy — the new env is written on the next run
Keep a local encrypted backup
Store the production .env in a password manager (1Password, Bitwarden) or an encrypted vault — not in a shared Slack channel or email. If the file is lost, the only source of truth left is the base64 blob in GitHub Secrets, which you can decode: gh secret get ENV_PROD | base64 -d
